## Findings

- **P0 — plaintext admin key reaches a log.** `/admin/rotate-key` prints `NEW_API_KEY` to stdout; launchd captures that stream. Remove the print and retrieval file, return the key once through an authenticated, CSRF-protected response, and rotate the DB credential transactionally. `server/src/wispralt_server/routes/admin.py:67`, `server/src/wispralt_server/routes/admin.py:120`, `server/src/wispralt_server/routes/admin.py:127`, `scripts/server-launchd.sh:13`
- **P1 — admin mutations lack CSRF checks.** User/key create, revoke and rotate POST handlers accept the session cookie but do not call `verify_csrf`; the login and insights-trigger POSTs do. Add the shared CSRF dependency to every cookie-authenticated mutation. `server/src/wispralt_server/auth.py:251`, `server/src/wispralt_server/routes/admin_ui.py:133`, `server/src/wispralt_server/routes/admin_ui.py:353`, `server/src/wispralt_server/routes/admin_ui.py:405`, `server/src/wispralt_server/routes/admin_ui.py:478`, `server/src/wispralt_server/routes/admin_ui.py:554`, `server/src/wispralt_server/routes/admin_data.py:269`
- **P1 — team insight “upsert” can duplicate rows.** Its composite SQLite primary key contains nullable `api_key_id`, and team inserts pass `NULL`; SQLite permits multiple such keys. Use a non-null scope key or separate partial unique indexes, then deduplicate existing team rows. An in-memory SQLite reproduction inserted two rows with the same week and team scope. `server/src/wispralt_server/jobs/store.py:259`, `server/src/wispralt_server/jobs/store.py:270`, `server/src/wispralt_server/jobs/store.py:505`, `server/src/wispralt_server/insights/cron.py:336`
- **P1 — the two databases can disagree on ownership and availability.** SQLite history uses Postgres user IDs without a local FK; the portal and insights skip work when Postgres is unavailable, although transcripts remain in SQLite. Move identities and usage into the same SQLite database, retain IDs during import, and add FKs. `server/src/wispralt_server/jobs/store.py:184`, `server/src/wispralt_server/routes/admin_ui.py:67`, `server/src/wispralt_server/insights/cron.py:115`
- **P2 — usage is lossy by design.** The bounded queue drops oldest events on overflow; failed Postgres flushes drop batches. Decide whether local usage is audit data, then persist synchronously or use a durable outbox. `server/src/wispralt_server/usage/queue.py:53`, `server/src/wispralt_server/usage/writer.py:91`
- **P2 — sensitive text can enter logs.** The Swift client logs the full dictation response through a logger marking messages public; malformed insight responses log their first 200 characters. Log metadata only. `client/WisprAlt/Server/DictationAPI.swift:189`, `client/WisprAlt/Util/Logger.swift:17`, `server/src/wispralt_server/insights/cron.py:250`
- **P2 — privacy and scheduling need explicit choices.** Transcript sweeps delete dictations and clear job text after 90 days; weekly insights send transcript text to OpenRouter and default to Sunday 23:00 Los Angeles time. Make retention, opt-in and timezone visible in the new portal. `server/src/wispralt_server/jobs/store.py:960`, `server/src/wispralt_server/insights/cron.py:197`, `server/src/wispralt_server/insights/cron.py:227`, `server/src/wispralt_server/config.py:153`, `server/src/wispralt_server/config.py:184`

## Risks/gotchas

Use a **read-only Postgres snapshot/export**, import users with original IDs before usage rows, reconcile counts and hashes, copy the SQLite DB using SQLite backup semantics, and switch only after validation. Plaintext bearer keys cannot be recovered from SHA-256 hashes; preserve valid hashes for Local mode or issue replacements. Archive `fallback_events` separately rather than silently treating them as ordinary usage. `server/migrations/2026-04-27-v1-wispralt-schema.sql:29`, `server/migrations/2026-04-27-v1-wispralt-schema.sql:54`, `server/src/wispralt_server/users/store.py:67`, `server/migrations/2026-05-05-v3-fallback-events.sql:14`
