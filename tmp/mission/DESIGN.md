# Target design (Part 1, 2026-11-07)

Guiding rule from the owner: clean, concise, future-proof, reusable; no abstraction for show.

## 1. Two modes, one client
- `Settings.mode: online | local`, default **online**, switched from the menu bar ("Online (OpenAI)" / "Local server"). Mode is captured at recording start, so one recording never spans providers.
- One seam, no framework: `protocol DictationSession` (the shape `DictationStreamSession` already has: `enqueueChunk`, `finalize(tail:smartFormat:)`, `abort`). `DictationRecorder` holds the protocol. Three implementations:
  - `ServerStreamSession` (today's actor, Local)
  - `OpenAIBatchSession` (file-style models: ignores chunks, POSTs the whole recording at stop to `/v1/audio/transcriptions`)
  - `OpenAIRealtimeSession` (live models: WebSocket Realtime transcription session, chunks forwarded as they are cut)
- **Model catalog** = one static Swift table (`OpenAIModels.swift`): id, kind (file|live), $/min, status/retire date. The picker in Advanced renders it with the price in small secondary text; deprecated models tagged "retires Feb 26, 2027". Default `gpt-transcribe`. Diarize model omitted (meetings gone).
- **Keys:** the OpenAI key lives in Keychain `co.wispralt.openai` (SecureField in Advanced + `security add-generic-password` docs). Sent only as a Bearer header to api.openai.com. Never logged. The Local server key stays at `co.wispralt`.
- **Client-local history:** "Copy last dictation" and the recent list come from a small client store in both modes (no server round trip). Server history stays for the Local portal/analytics.
- **Mercury in Online mode:** optional client-side call to OpenRouter chat with the same prompt and safety rules as the server (shared rules spec + identical test vectors). Off by default, key in Keychain `co.wispralt.mercury`. In Local mode the server keeps doing it.
- **File transcription in Online mode:** AudioExtractor → mono 16 kHz AAC/m4a; if it is over ~24 MB, split on silence-free fixed windows with offsets; gpt-transcribe per chunk; outputs TXT + JSON. SRT/VTT only when the chosen model returns timestamps (whisper-1, deprecated) or in Local mode; the UI says so plainly.
- Local mode: loopback `http://` allowed; remote hosts must be `https://`.

## 2. Local host (server)
- **Single SQLite DB** (WAL) owned by the host: `schema_migrations, users, api_keys, usage_events, dictations, jobs, weekly_insights` (schema per audit-codex-data-ops.md, with person/team uniqueness fixed and FKs). Supabase/asyncpg removed from the runtime; a read-only Postgres export/import lives in the CLI (Part 7).
- **Package split:** `wispralt` Python package with a light base (CLI, API, DB, portal) and a `host` extra for MLX (parakeet-mlx, mlx-whisper). Client-only machines never install ML.
- **Inference seam:** `backends/` with `dictation` (Parakeet) and `files` (Whisper turbo) behind two plain functions/classes selected in config. The pipeline loads only what the job needs. MLX is the only backend shipped; unsupported hardware gets a clear `doctor` message.
- **Files package:** `meeting/` → `files/` (pipeline mono path, output writers incl. SRT/VTT helpers used by /v1). Routes `/transcribe/file` (+chunked) and `/transcribe/file/{id}` for poll/download/delete, with owner checks. No legacy aliases (the client is the only consumer and ships in lockstep).
- **Security fixes:** owner/admin checks on job routes, no key printing, CSRF on every cookie mutation, chunk-index verification, `/v1` unknown model → `model_not_found`, metadata-only logging.
- **Mercury:** measured budget and threshold, reason-coded result (`applied | skipped:<reason> | failed:<reason>`) surfaced in the response and portal; never a fake success.

## 3. CLI + install
- `wispralt` (Python argparse, console script) with `setup [--role host|client|both] [--non-interactive ...]`, `status`, `doctor`, `start|stop|restart`, `users add|list|revoke`, `keys create|rotate|revoke`, `import`, `backup|restore`, `update`, `uninstall`, `tunnel` (optional Cloudflare).
- `install.sh` stays the one-line bootstrap: Homebrew/ffmpeg/uv check, `uv tool install` of the package (with `host` extra when chosen), then `wispralt setup`. Idempotent: never regenerates working credentials or overwrites data; resumable state file.
- launchd plists generated by the CLI from templates; no hardcoded user, host, domain or repo. Update channel configurable (default: this repo's public releases).

## 4. Portal + insights
- Keep FastAPI + Jinja + local HTMX/Alpine; redesign templates/CSS (no SPA framework). First-admin bootstrap token printed once by `wispralt setup` (shown in the terminal only, never logged), invites as one-time links, keys shown once.
- Monitoring page fed by real measurements (psutil, model readiness, job queue, DB health, last-seen per key vs active connections).
- Data tab: measured stats computed locally always; AI insights optional (explicit provider + cost cap), each claim linked to the dictation/job ids it came from; rerun/backfill.
