## Findings

- **P0 — Online and Local routing does not exist.** Dictation and file jobs require `Settings.serverURL`; `ServerClient` attaches the existing server bearer key. Add a persisted mode choice in `Settings`, route at `DictationAPI.transcribe` and the file-job entry point, and add a separate OpenAI Keychain item and provider for direct Online requests. Keep `ServerClient` for Local. `client/WisprAlt/Storage/Settings.swift:23`, `client/WisprAlt/Server/ServerClient.swift:82`, `client/WisprAlt/Server/ServerClient.swift:92`, `client/WisprAlt/Server/DictationAPI.swift:65`, `client/WisprAlt/App/MenuBarController+Transcription.swift:39`

- **P1 — Local HTTP hosts are rejected.** Settings accepts and reloads only `https`, and the UI repeats that rule. Permit loopback HTTP for Local mode while retaining appropriate validation for remote hosts. `client/WisprAlt/Storage/Settings.swift:40`, `client/WisprAlt/Storage/Settings.swift:218`, `client/WisprAlt/UI/SettingsView.swift:125`

- **P1 — “Streaming” is coupled to FastAPI’s chunk protocol.** Recorder startup creates `DictationStreamSession`, and its chunks use `/transcribe/dictate/stream/...`. For live Online models, place a Realtime WebSocket session behind the recorder’s existing chunk/session seam; select it at recording start so a mode change cannot split one recording across providers. `client/WisprAlt/Capture/DictationRecorder.swift:453`, `client/WisprAlt/Capture/DictationRecorder.swift:660`, `client/WisprAlt/Server/DictationStreamSession.swift:152`, `client/WisprAlt/Server/DictationAPI.swift:69`

- **P1 — File-job recovery can report completion without saving results.** Only the job ID is persisted; resumed polling has lost the output directory and stem and performs no download. Persist those fields with the job ID, then finish the download after relaunch. `client/WisprAlt/App/MenuBarController+Transcription.swift:197`, `client/WisprAlt/App/MenuBarController+Transcription.swift:412`, `client/WisprAlt/App/MenuBarController+Transcription.swift:424`

- **P1 — OpenRouter transcription fallback has a separate client credential and telemetry queue.** Remove its third ladder attempt, `callOpenRouter`, parser, fallback model, Keychain methods, and `DictationFallbackQueue`; retain the smart-formatting toggle and `X-Smart-Format` request signal for the Local server’s Mercury path. `client/WisprAlt/Server/DictationAPI.swift:39`, `client/WisprAlt/Server/DictationAPI.swift:147`, `client/WisprAlt/Server/DictationAPI.swift:209`, `client/WisprAlt/Storage/KeychainHelper.swift:111`, `client/WisprAlt/Storage/DictationFallbackQueue.swift:30`, `client/WisprAlt/UI/SettingsView.swift:433`, `client/WisprAlt/Server/DictationAPI.swift:114`

- **P2 — Packaging and coverage lag the client.** `Package.swift` targets macOS 15 while `Info.plist` advertises 14; the sole test target covers pure injection predicates, not hotkeys, providers, streaming, or uploads. Align the minimum version and add focused tests around provider routing and preserved file jobs. `client/Package.swift:6`, `client/WisprAlt/Info.plist:21`, `client/Package.swift:60`, `client/Tests/WisprAltCoreTests/InjectionPredicateTests.swift:4`, `client/Tests/WisprAltCoreTests/SecureFieldGateTests.swift:4`

## Risks/gotchas

The update checker points to `omdiidi/miniWhisper` and runs that account’s remote `install.sh`; OpenRouter requests also send that repository as `HTTP-Referer`. Replace those literals before distributing. The bundle ID, defaults suite, Keychain services, and background-session ID use `co.wispralt` and need a coordinated migration if renamed. No literal client team ID or gist reference appeared in the source search; the distribution script takes `TEAM_ID` as input. `client/WisprAlt/Update/UpdateChecker.swift:37`, `client/WisprAlt/Update/UpdateChecker.swift:143`, `client/WisprAlt/Server/DictationAPI.swift:245`, `client/WisprAlt/Info.plist:11`, `client/WisprAlt/Storage/Settings.swift:19`, `client/WisprAlt/Storage/KeychainHelper.swift:33`, `client/WisprAlt/Server/ServerClient.swift:53`, `scripts/build-client.sh:10`

## Test commands that actually work

From the repo root, the source-defined checks are `cd client && swift test --filter WisprAltCoreTests` and `cd client && swift build`; the packaged app path is `bash scripts/build-client-local.sh` and requires an Apple Development signing identity. These commands were **not run**: this read-only environment denied Swift’s temporary cache creation, and its active developer directory has Command Line Tools rather than Xcode.
